# Журнал решений

Руководитель проекта добавляет сюда только принятые решения. Пока решения нет,
агенты используют текущий код и не расширяют требования сами.

## Открытые решения

| ID | Решение, которое требуется | Почему блокирует работу | Владелец |
|---|---|---|---|
| ADR-001 | Граф статусов: разрешать ли прямой переход в `lost`, нужен ли комментарий причины, можно ли возвращать `won/lost` в `draft` | UI, права, API и отчёты должны одинаково понимать статус | PM + владелец продукта |
| ADR-002 | Видимость ТКП: все сотрудники видят общий портфель или нужны `OwnerId`/команды/ACL | Меняет запросы, права и миграцию | PM + владелец продукта |
| ADR-003 | Каноническое представление шкафа: явные габариты, серия, IP, способ монтажа и состав | Нельзя превращать прототипы тепло/сборок в продукт по строке имени | PM + backend + инженерный эксперт |
| ADR-004 | Нормативная база и ответственность за её обновление | ГОСТ/ПУЭ-валидации нельзя выдавать как нормативно верные без источника и версии | PM + инженерный эксперт |
| ADR-005 | Политика учёта времени и персональных данных | Определяет автоматический трекинг, хранение, отчёты и доступ | PM + владелец продукта |
| ADR-006 | Целевой production-контур: домен, TLS, секреты, резервное копирование, журналирование | Нельзя безопасно выпускать систему с demo-config | PM + эксплуатация |
