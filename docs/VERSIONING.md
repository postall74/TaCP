# Версии проекта

Версия проекта записывается как `ver X.Y.Zb` для разработки и как
`ver X.Y.Z` для принятого выпуска. Имя Git-тега использует тот же номер с
префиксом `v`: например, `v0.7.4b` и `v0.7.4`. Это собственная схема проекта,
а не обозначение уровней совместимости SemVer.

| Часть | Значение | Когда меняется |
|---|---|---|
| `X` | Полный релиз проекта | `0` до принятия полного релиза; при принятии полного релиза увеличивается на 1, `Y` и `Z` сбрасываются в 0 |
| `Y` | Крупные изменения | Увеличивается при принятии крупного функционального изменения; `Z` сбрасывается в 0 |
| `Z` | Небольшие изменения | Увеличивается при принятии небольшого функционального изменения или исправления без крупного изменения |
| `b` | Версия в разработке | Добавляется к номеру до завершения проверок и принятия соответствующего выпуска; после принятия убирается |

Пример: `ver 0.7.4b` означает, что полного релиза проекта ещё не было,
принята седьмая серия крупных изменений, готовится четвёртое небольшое
изменение. После приёмки этого выпуска номер становится `ver 0.7.4`.
Следующее небольшое изменение — `ver 0.7.5b`, следующее крупное —
`ver 0.8.0b`. Первый полный релиз проекта — `ver 1.0.0` после его
отдельной приёмки.

Опубликованные теги неизменяемы: повторная сборка той же версии определяется
SHA коммита, а не переносом тега. Git-тег создаёт только PM, аннотированным,
на проверенном коммите `main` после независимой QA, зелёного CI и остальных
release gates. Для полностью закрытой потребности описание тега перечисляет
закрытые `NEED-*`. Частичный результат не получает релизный тег; номер с `b`
может использоваться для обозначения текущей разработки без публикации тега.

Ранее опубликованные имена, включая `v0.7.0`, не переименовываются и не
перемещаются. Это правило применяется к следующим версиям.
