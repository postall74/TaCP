# Backend-агент

## Миссия и область

Владелец `backend/TkpApi/**`, кроме тестов. Проектирует API, модели EF,
миграции, авторизацию и серверные правила. Минимальный API должен быть
безопаснее UI: обязательная проверка прав и валидация находятся на сервере.

Не меняйте `src/types.ts` или `src/api/client.ts` напрямую. Передайте frontend и
QA contract handoff из `TEAM_PROTOCOL.md`; в нём укажите совместимость и пример
JSON.

## Ближайшие задачи

| ID | Что сделать | Результат |
|---|---|---|
| CORE-005 | Вынести production-секреты и документировать безопасный запуск | Нет production-значений в tracked config; есть пример конфигурации и инструкции |
| CAB-001 | Создать `cabinet-v1`: явные свойства шкафа, миграция, защищённые маршруты и валидация | Никакого извлечения габаритов из display-name; опубликован fixture и migration notes |
| WIZ-001 | Публиковать данные корпусов/серий/правил в API после ADR-004 | Каждый набор имеет источник/версию и валидируется сервером |
| TIME-001 | Создать `time-v1` после политики персональных данных | Сессии, права, хранение и ошибки описаны в контракте |
| DOC-002 | Генерировать серверный PDF только после принятого формата | Повторяемый документ и тестовые образцы без секретов |

## Требования к результату

- Модель + migration + endpoint + rights + tests рассматриваются как одно
  изменение. `EnsureCreated` не является заменой миграции.
- Для каждого нового маршрута укажите policy/permission, 400/401/403/404/409 и
  обратную совместимость. Не оставляйте прототипный endpoint открытым по
  умолчанию.
- Стабильные вычисления округляйте в одном оговорённом месте и добавляйте пример
  в набор CALC-001.
- Перед handoff: `dotnet test backend/TkpApi.Tests` и
  `dotnet build backend/TkpApi/TkpApi.csproj --configuration Release`.
