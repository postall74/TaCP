# Подтверждённое состояние проекта

Снимок составлен 22.09.2026 по исходникам и локальным проверкам. «Есть» означает,
что код присутствует; это не равнозначно готовности к промышленной эксплуатации.

## Реализовано в коде

- React 18 / TypeScript / Vite интерфейс: дашборд, редактор ТКП, мастер подбора,
  каталог, тарифы, документ А4/печать, Excel-экспорт и SVG-чертежи шкафов.
- Локальный режим с `localStorage` и серверный режим через `src/api/client.ts`;
  аутентификация, профиль и роли `admin`, `manager`, `engineer`.
- Чистые frontend-модули для расчёта, CSV, совместимости, составных шкафов и
  секционирования; для них существуют Vitest-тесты.
- ASP.NET Core 8 Minimal API, EF Core/PostgreSQL, Identity/JWT, Swagger,
  миграции, каталог, проекты, версии, мягкое удаление каталога и политики прав.
- Серверные вычислительные модули `CalcEngine`, `CatalogCsv`, `KitEngine`, а
  также прототипы `ThermalEngine`, `CabinetConfigurator` и
  `CabinetAssemblyService`.
- Отдельная административная область с пользователями, каталогом, статистикой и
  отображением учёта времени.

## Что проверено сейчас

Дополнение PM 2026-09-22: чтением `AuthExtensions.cs` подтверждены
`AllowAnonymous` на auth group и назначение роли из RegisterDto при регистрации.
Это блокер внешнего релиза SEC-001, а не доказанная эксплуатация уязвимости.
Docker/tenant-isolation пока только запланированы в [DEPLOYMENT_PLAN](DEPLOYMENT_PLAN.md).

Промежуточный отчёт QA CORE-002 на базе fbd78d0b, отдельный worktree:
после добавления `npm test` чистый `npm ci` успешен, 71 frontend и 57 backend
тестов прошли, backend Release build без предупреждений/ошибок. Typecheck
на исходной базе всё ещё выдаёт 9 диагностик; интеграция CORE-001 не проверена.
Эти данные получены из handoff QA, PM не повторял команды. Ниже сохранён
первоначальный baseline, различия установок не означают закрытие CORE-002.

| Проверка | Результат |
|---|---|
| `dotnet test backend/TkpApi.Tests --no-restore` | Успех: 57 xUnit-тестов |
| `dotnet build backend/TkpApi/TkpApi.csproj --configuration Release --no-restore` | Успех, 0 предупреждений и 0 ошибок |
| `node node_modules/typescript/bin/tsc --noEmit` | Ошибка: 10 ошибок типов |

| `node node_modules/vite/bin/vite.js build` | Не стартует по той же причине Rollup |

`npm run typecheck` и `npx vitest run` дополнительно не находят локальные shim-
команды. Это признак неполной установки `node_modules`, а не доказательство
ошибки в `package-lock.json`; воспроизводимость должен подтвердить QA после
чистого `npm ci` в своей среде.

Реальные ошибки TypeScript, независимые от Rollup:

- `src/admin/components/UsersPage.tsx`: компонентам `Input` передаётся не
  объявленный проп `type`; `Select` используется с `children` вместо обязательного
  `options`.
- `src/store.ts`: вызывается необъявленный `loadUsers`.

## Не считать готовым к релизу

- Нормативный пакет `research/normative/` является черновиком исследования.
  Полные тексты, точные пункты/таблицы/исключения, применимость ТР и договорные
  требования ещё не образуют верифицированную базу правил. ADR-003/004 остаются
  proposed; текущие эвристики шин, КЗ, нагрева, IP, PE, секционирования, УЗИП и
  safety нельзя представлять как доказательство полного соответствия.

- API конфигуратора шкафов, теплового расчёта и сборок существует, но не имеет
  методов в typed frontend-клиенте и не подключён к пользовательскому сценарию.
  Для этих маршрутов нужно отдельно проверить авторизацию, валидацию и контракт.
- Габариты шкафа извлекаются сервисом сборок из названия регулярным выражением с
  запасными значениями. Это прототип, а не доменная модель габаритов.
- Расчёт на TypeScript и `CalcEngine.cs` — две реализации. Их совпадение нельзя
  объявлять гарантированным, пока не появится набор одинаковых контрактных
  сценариев.
- Тарифы в `Program.cs` хранятся в памяти процесса; после перезапуска API они не
  являются подтверждённо персистентными.
- В `appsettings.json` лежат демонстрационные пароль БД, JWT-ключ и пароль
  администратора. Такой файл нельзя использовать как production-конфигурацию.
- В репозитории два пересекающихся GitHub Actions workflow, а `.gitignore` не
  игнорирует каталоги `backend/**/bin` и `backend/**/obj`. Генерируемые файлы уже
  видны в рабочем дереве.
