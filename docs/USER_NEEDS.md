# Реестр исходных потребностей пользователя

Источник: замечания пользователя от 2026-09-29. Это реестр результата, а не
готовая техническая спецификация. Детальные требования должны быть отражены в
ROADMAP/ADR/контракте до реализации.

## Правило закрытия потребности

Потребность получает статус `closed` только когда одновременно выполнены:

1. Все связанные критерии ROADMAP и контрактов приняты PM.
2. Независимый QA проверил пользовательский сценарий и отсутствие регрессии.
3. Пользовательская инструкция описывает функцию простым языком и содержит
   актуальные скриншоты ключевых шагов.
4. Изменения слиты в `main`, CI зелёный, remote SHA сверен.
5. Создан новый аннотированный GitHub-тег версии, указывающий на проверенный
   commit `main`; в описании версии перечислены закрытые `NEED-*`.

Частичная инфраструктура, внутренний API или отдельный экран не закрывают
потребность целиком. Если функция покрывает только часть, статус остаётся
`partial` и тег по этой потребности не создаётся.

## Обязательная проверка каждого handoff

PM сопоставляет новый diff с этой матрицей. Если реализация потенциально
закрывает потребность, handoff и QA-отчёт явно перечисляют `NEED-*`, сценарии
приёмки и путь к пользовательской инструкции/скриншотам. Без этого функция
может быть технически принята, но потребность остаётся открытой.
