## Независимый браузерный smoke

QA dev server `http://127.0.0.1:5187`, изолированный origin/localStorage.
Проверено в светлой и тёмной темах:

1. Открыть локальную регистрацию: ФИО, роль, кнопка создания доступны.
2. Вписать `http://127.0.0.1:59999` в API URL. Экран сразу становится входом,
   поля регистрации и demo-подсказка исчезают; есть обращение к администратору.
3. Отправить синтетические email/password: `Failed to fetch`, экран остаётся
   формой входа; ложного успеха и перехода в приложение нет.
4. Очистить API URL: возвращается локальный вход, не устаревший register mode.
5. В тёмной теме открыть регистрацию заново, создать `qa-sec002@example.test`
   (синтетическое QA-имя), увидеть «Аккаунт создан — войдите», войти теми же
   данными и увидеть профиль инженера. Никакой реальный API не использовался.

Тёмная серверная форма просмотрена на screenshot: поля и уведомление доступны.
В конце возвращена светлая тема, выполнен выход, API URL пустой.
Тестовый пользователь сохранён только в localStorage QA origin :5187.
