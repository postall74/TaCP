# Шкаф·Про — конфигуратор пустых и преднаполненных шкафов

Фронтенд-модуль дорожной карты ТКП·Про, пункт **Б.1**: отдельный конфигуратор,
в котором корпус шкафа собирается как изделие с **заказным шифром** и вставляется
в ТКП одной позицией.

## Что сделано (Б.1)

**Конфигуратор** (`src/components/CabinetConfigurator.tsx` — существовал, доведён
до рабочего состояния; все зависимые модули созданы с нуля):

- **Пустые и преднаполненные шкафы**: корпус по образцу ПРОВЕНТО ШРС / DKC CQE N
  либо корпус + преднаполнение (несколько АВ на распределение питания
  микроклимата и освещения — из справочника).
- **Порядок подбора**: тип монтажа (напольный / навесной) → производитель →
  направление работ → габариты из сетки типоразмеров → степень защиты IP.
- **Комплект поставки** (`src/utils/cabinetTemplates.ts`): рама с потолочной
  панелью, панели кабельного ввода, монтажные траверсы (2 + 1 от 2000 мм),
  двери (от 1000 мм — две распашные) с замками и ключами, панель задняя,
  панели боковые, панель монтажная, цоколь 100 мм с фланцами; для навесных —
  цельносварной корпус + кронштейны. Состав редактируется (переименование,
  количество, свои компоненты).
- **Заказной шифр**: авто-генерация `ШН-2000.800.600-IP54[-П]`
  (ШН — напольный, ШВ — навесной, «-П» — преднаполненный) или свой;
  наименование — авто или своё.
- **Часы сборки** — рекомендованные по габариту, включаются в стоимость изделия.
- **Строка для ТКП** ровно в требуемой форме: «Шкаф напольный распределительный
  габаритами 2000×800×600 мм (В×Ш×Г), степень защиты IP54. Комплект поставки:
  рама с потолочной панелью; …» — копируется в буфер одной кнопкой.
- Права (`src/utils/roles.ts`): создание/правка — все сотрудники, удаление —
  менеджер/админ; локальный режим = админ.
- Хранение — localStorage (zustand persist, ключ `shkaf-pro-v1`); в полной
  версии синхронизируется с БД.

**Исправлено в существующем компоненте**: типизация `MOUNTS`
(`as const` давал литеральные кортежи — `includes()` не проходил проверку
типов), сигнатура `templateDocLine` (лишний параметр `mount`).

## Структура

```
src/
├─ App.tsx                        — оболочка: сайдбар (шифры, статистика), тосты
├─ components/CabinetConfigurator.tsx — конфигуратор (список + форма шаблона)
├─ components/ui.tsx, icons.tsx   — UI-кит и иконки
├─ data/catalog.ts                — справочник (АВ, АВДТ, контакторы, БП)
├─ utils/cabinetTemplates.ts      — чистая логика шаблонов
├─ utils/roles.ts, utils.ts       — права, форматирование
└─ store.ts                       — zustand + persist
```

## Запуск и проверка

```powershell
npm install
npm run dev        # http://localhost:3000
npm run build      # продакшен-сборка (dist/)
npm run typecheck  # tsc --noEmit
```

Проверка шага:

1. «Новый шаблон» → напольный 2000×800×600 IP54 → комплект из 9 позиций
   пересчитывается при смене габарита; дверей — 2 (ширина ≥ 1000).
2. Добавить преднаполнение (АВ 1P C6 на освещение, 2P C16 на вентиляцию) →
   шифр получает суффикс «-П», бейдж «преднаполненный».
3. «Строка для ТКП» → в буфере строка требуемого формата.
4. Сохранить → карточка в списке; перезагрузить страницу → шаблон на месте
   (localStorage). Удаление доступно по ролям.
