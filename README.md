# Шкаф·Про — конфигуратор пустых и преднаполненных шкафов

Фронтенд-модуль дорожной карты ТКП·Про, пункт **Б.1**: отдельный конфигуратор,
в котором корпус шкафа собирается как изделие с **заказным шифром** и вставляется
в ТКП одной позицией.

## Что сделано (Б.1)

**Конфигуратор** (`src/components/CabinetConfigurator.tsx` — существовал, доведён
до рабочего состояния; все зависимые модули созданы с нуля):

- **Пустые и преднаполненные шкафы**: корпус по образцу ПРОВЕНТО ШРС / DKC CQE N
  либо корпус + преднаполнение (несколько АВ на распределение питания
  микроклимата и освещения — из справочника).
- **Порядок подбора**: тип монтажа (напольный / навесной) → производитель →
  направление работ → габариты из сетки типоразмеров → степень защиты IP.
- **Комплект поставки** (`src/utils/cabinetTemplates.ts`): рама с потолочной
  панелью, панели кабельного ввода, монтажные траверсы (2 + 1 от 2000 мм),
  двери (от 1000 мм — две распашные) с замками и ключами, панель задняя,
  панели боковые, панель монтажная, цоколь 100 мм с фланцами; для навесных —
  цельносварной корпус + кронштейны. Состав редактируется (переименование,
  количество, свои компоненты).
- **Заказной шифр**: авто-генерация `ШН-2000.800.600-IP54[-П]`
  (ШН — напольный, ШВ — навесной, «-П» — преднаполненный) или свой;
  наименование — авто или своё.
- **Часы сборки** — рекомендованные по габариту, включаются в стоимость изделия.
- **Строка для ТКП** ровно в требуемой форме: «Шкаф напольный распределительный
  габаритами 2000×800×600 мм (В×Ш×Г), степень защиты IP54. Комплект поставки:
  рама с потолочной панелью; …» — копируется в буфер одной кнопкой.
- Права (`src/utils/roles.ts`): создание/правка — все сотрудники, удаление —
  менеджер/админ; локальный режим = админ.
- Хранение — localStorage (zustand persist, ключ `shkaf-pro-v1`); в полной
  версии синхронизируется с БД.

**Исправлено в существующем компоненте**: типизация `MOUNTS`
(`as const` давал литеральные кортежи — `includes()` не проходил проверку
типов), сигнатура `templateDocLine` (лишний параметр `mount`).

## Структура

Инженерный инструмент для компаний, собирающих **НКУ** (низковольтные комплектные
устройства), **АСУ ТП / АСУ Э** и **системы электрообогрева**: от опросника заказчика
до подписанного документа ТКП с полной экономикой (себестоимость, маржа, рентабельность).

## Что умеет

### Конструктор ТКП
- **Дашборд** с воронкой «в работе / выполнено / проиграно», конверсией и средним чеком.
- **Дерево шкафов** (ГРЩ, ВРУ, АВР, Шкаф ПЛК, ЩУО, ЗИП…) с inline-правкой количеств,
  закупочных цен и трудозатрат по ролям (сборка / проектирование / ППО).
- **Мастер подбора (опросник, 14 шагов)**: корпус (готовый из справочника /
  составной комплект / ручной ввод), АВР (БАВР / контакторы / рубильник, 2/3/5
  вводов, 1-ф/3-ф), ввод и отходящие линии с учётом электроэнергии, **заземление**
  (TN-S/TN-C-S/TT/IT + контроль изоляции), УЗИП (силовые + RS-485/Ethernet/каналы
  ПЛК), кнопки и индикация (**интерактивный макет дверцы** — перетаскивание
  элементов, свои подписи сверху/снизу), **измерительные приборы** (WB-XXX на
  вводе, амперметры/вольтметры, ТТ поканально на фазы отходящих АВ),
  **шины по току нагрузки**, компоновка «стена к стене», микроклимат, **конфигуратор
  ПЛК** (DI/DO/AI/AO + резерв + барьеры искрозащиты), **секционирование** (опросник
  форм 1…4b), **работы и ППО** (нормо-часы с живым расчётом по тарифам),
  **ЗИП % (мин. 1 шт)**, транспорт, сводка.
- **Составные шкафы** по образцу ПРОВЕНТО / DKC CQE N: корпус комплектуется из
  каркаса, крыши/основания, панелей, дверей и цоколей (CQE N напольный IP54 и
  навесной IP66); ряд «стена к стене» автоматически пересчитывает панели
  (ряд+1), стыковые комплекты (ряд−1) и цоколи, учитывает доп. траверсы.
- **Проверка совместимости** (`src/utils/rules.ts`): отходящий автомат ↔ шина по
  номинальному току, УЗИП без вводного АВ, ПЛК без БП 24 В, панель без ПЛК,
  греющий кабель без терморегулятора, формы разделения без шинного отсека —
  с переходом к шкафу и бейджем на вкладке.
- **Секционирование** (ГОСТ IEC 61439-2): функциональные отсеки (вводной,
  отходящих линий, управления, шинный, кабельный), перегородки с ценой от
  высоты шкафа, формы разделения 1…4b с автопроверкой требований; комплект
  отсеков в составе шкафа, в документе и на структурной схеме.

### Экономика (единая модель)
- В справочнике хранится **только закупочная цена**. Цена продажи вычисляется
  **один раз**: `закупка × (1 + наценка %)` — наценка задаётся в проекте.
- Себестоимость: оборудование + ТЗР % + сторонние + ФОТ (часы × ставки ролей) +
  доп. затраты + непредвиденные % + командировки + СМР + ПНР.
- Продажа → скидка % → **НДС % (редактируемый)** → ИТОГО. Маржа, наценка,
  рентабельность — автоматически. Ставки чел·часов — на странице **«Тарифы»**.

### Документы
- Предпросмотр **А4**: шапка с реквизитами, разделы по шкафам, сводная стоимость,
  условия, подписант **и исполнитель**; приложения (перечень автоматизации,
  структурная схема). Экспорт: **PDF** (печать), **Word (.doc)**.
- **Excel (.xlsx)**: вкладка на каждый шкаф + «ИТОГО» + **«Расчёт по производству»**
  (ТЗР, ФОТ, непредвиденные, маржа, наценка, рентабельность, СМР/ПНР, прибыль) +
  «Бюджет проекта».

### Справочник и данные
- ~80 позиций (Schneider, ABB, IEK, КЭАЗ, EKF, ОВЕН, Мохa, ССТ…), направления
  НКУ / АСУ / Обогрев / универсальное; CRUD + **импорт прайсов CSV** (8 колонок,
  «1 800,50» в русской локали — ок).
- **Версии ТКП**: снимок, восстановление, сравнение сумм.
- Тёмная/светлая тема, автосохранение в localStorage.

### Сервер и доступ
- **C#-бэкенд** (`backend/TkpApi`, ASP.NET Core 8 Minimal API + EF Core + PostgreSQL):
  REST-контракты зеркалят модель фронтенда, Swagger с JWT-Authorize.
- **Вход обязателен всегда.** Двухрежимная авторизация: с бэкендом —
  ASP.NET Identity + JWT, без бэкенда — пользователи в localStorage
  (админ `admin@tkp.local / Admin#12345`). Роли `admin / manager / engineer`.
  **Матрица прав**: удаление ТКП, решения «выиграно/проиграно», удаление/импорт
  справочника и реквизиты компании — менеджер/админ; тарифы и пользователи — админ.
  Инженер пополняет/правит справочник (без удаления и импорта, с проверкой на дубль)
  и меняет свой телефон. Страница «Пользователи» со сменой ролей.
- **Поиск и фильтры портфеля**: по названию/номеру/заказчику/контакту,
  направлению, датам создания + вкладки статусов.
- Фронтенд **двухрежимный**: без URL — локально (localStorage); с URL — данные
  гидрируются с сервера, мутации синхронизируются (оптимистично + дебаунс 700 мс).
- **Онлайн-режим в локальной сети**: бэкенд сам раздаёт собранный `dist/` — вся
  команда открывает один адрес `http://<сервер>:5085`; фронтенд **автоопределяет**
  API на том же origin, при обрыве связи копит **офлайн-очередь** и доотправляет её.
- **«Корзина» справочника**: удалённые позиции хранятся 90 дней, проекты видят
  пометку и срок; реквизиты компании — **по учётной записи** (в БД).
- **Схема БД — EF-миграции** с авто-baseline (см. `backend/MIGRATIONS.md`);
  эндпоинты данных закрыты политиками `Staff`/`AdminOnly`/`ManagerUp`.

## Быстрый старт

Полная пошаговая инструкция (Node, .NET, PostgreSQL, запуск, troubleshooting) — в
**[QUICKSTART.md](./QUICKSTART.md)**. Коротко:

```bash
# фронтенд
npm install && npm run dev            # http://localhost:3000

# бэкенд (из backend/TkpApi)
createdb -U postgres tkp              # один раз
dotnet run                            # http://localhost:5085, Swagger: /swagger
```
src/
├─ App.tsx                        — оболочка: сайдбар (шифры, статистика), тосты
├─ components/CabinetConfigurator.tsx — конфигуратор (список + форма шаблона)
├─ components/ui.tsx, icons.tsx   — UI-кит и иконки
├─ data/catalog.ts                — справочник (АВ, АВДТ, контакторы, БП)
├─ utils/cabinetTemplates.ts      — чистая логика шаблонов
├─ utils/roles.ts, utils.ts       — права, форматирование
└─ store.ts                       — zustand + persist
```

## Запуск и проверка

Полная карта с делением на «Сделано» / «Осталось» — в [DOCS.md § 12](./DOCS.md#12-дорожная-карта).
Ключевые направления в работе:

- **А. Конструктор**: переработка шагов «Корпус» и «Ввод и линии», УЗИП из БД
  (~~интерактивный макет дверцы~~, ~~измерительные приборы WB-XXX~~,
  ~~работы и ППО с живым расчётом~~ — готово).
- **Б. Шкафы и графика**: конфигуратор пустых/преднаполненных шкафов с заказным
  шифром, расчёт тепловыделений, общий вид шкафа по ГОСТ, соединение «дверь к
  задней стенке».
- **В. Аналитика**: отдельная админ-панель (статистика по направлениям и
  производителям), регистрация времени подготовки ТКП (только админ).
- **Г. Документы**: АВР-однолинейная схема, серверный PDF, согласование.
- **Д. Инфраструктура**: персист секционирования, парсеры прайсов, код-сплиттинг.

Проверка шага:

1. «Новый шаблон» → напольный 2000×800×600 IP54 → комплект из 9 позиций
   пересчитывается при смене габарита; дверей — 2 (ширина ≥ 1000).
2. Добавить преднаполнение (АВ 1P C6 на освещение, 2P C16 на вентиляцию) →
   шифр получает суффикс «-П», бейдж «преднаполненный».
3. «Строка для ТКП» → в буфере строка требуемого формата.
4. Сохранить → карточка в списке; перезагрузить страницу → шаблон на месте
   (localStorage). Удаление доступно по ролям.
